### 03 · Quote_Flow — B2B Pricing, Catalogue Ingestion &amp; Margin Intelligence Engine

**Status:** Active Collaborative Development on `Feature/Backend-Foundation` (`179` Passing Unit Tests + `18` PG16 Integration Tests) · Next.js 15 Frontend Planned Post-API Freeze

Co-developed with a Data Science graduate (with my role leading Software Engineering &amp; Backend Architecture), **Quote_Flow** is a multi-tenant B2B pricing and quotation engine built for South African solar, electrical, and backup-power contractors. #### Technical Implementation &amp; Scope Boundaries

- **Technology Stack:** Python 3.13, FastAPI, PostgreSQL 16, SQLAlchemy 2.0, Alembic, Pydantic v2 (`ExactDecimal`), Argon2 / JWT Authentication, Docker Compose, Pytest, Ruff *(Next.js 15, TypeScript &amp; Tailwind CSS planned)*.
- **Why IEEE 754 Floats Are Rejected (`ExactDecimal` → `NUMERIC`):**
  - Binary floating-point representation introduces mantissa drift (`0.1 + 0.2 === 0.30000000000000004`), which corrupts VAT, markup, and gross-margin rollups across multi-item contractor quotes.
  - Quote_Flow enforces Pydantic v2 `ExactDecimal` validators at the API boundary (rejecting raw JSON floats with `HTTP 422`) and persists all monetary and percentage columns as PostgreSQL `NUMERIC(14,4)` / `NUMERIC(7,4)` with zero floating-point columns in the schema.
- **5-Tier Supplier SKU Matching &amp; Immutable Revisions:**
  1. **Stage 01 · Canonical ASCII SKU Normalisation (`COLLATE "C"`):** Strips punctuation/whitespace into uppercase ASCII keys constrained by PostgreSQL regex `CHECK` rules.
  2. **Stage 02 · Explicit Supplier Alias Lookup:** Maps wholesaler SKU codes to canonical catalogue items across historical batches.
  3. **Stage 03 · Trigram Similarity &amp; Category Candidate Scoring:** Flags probable matches inside isolated staging batches for human review.
  4. **Stage 04 · Preferred Supplier Baseline Guard:** Prevents lower-confidence CSV/XLSX imports from overwriting approved primary supplier unit costs.
  5. **Stage 05 · 4-Column Composite Quotation Revision Key:** Binds `(tenant_id, quote_group_id, revision_number, id)` to immutable `supplier_price_snapshots` and locks family lineages with `SELECT ... FOR UPDATE` when cloning revisions.
- **Implemented vs. Planned:**
  - **Implemented &amp; Tested (`Feature/Backend-Foundation`):** 12 SQLAlchemy 2.0 ORM models, baseline PostgreSQL 16 Alembic migration (`6fe0f6e79dd9`), 6 core FastAPI v1 routers, Argon2/JWT auth, **17 unit test files (179 passing tests)**, and **10 PostgreSQL 16 integration test files (18 tests)**.
  - **Collaborator Branches &amp; Planned Frontend:** `origin/Feature/Ingestion-Engine` and `origin/develop` integrate supplier CSV/XLSX batch parsing; `frontend/` currently contains `.gitkeep` placeholders only while the Next.js 15 UI is scheduled after API contract freeze.

### End-to-End Request &amp; Persistence Lifecycle

```text
Visitor Browser (HTTPS)
  └──► Vercel Edge Network (index.html, assets/css/styles.css, assets/js/script.js, HTTP 206 MP4 Range streams)
         └──► GET /api/visitors (api/visitors.js — Node.js Serverless Function on Vercel)
                └──► @neondatabase/serverless (Server-side DATABASE_URL over TLS)
                       └──► Neon PostgreSQL (visitor_counter atomic ON CONFLICT DO UPDATE)
```

1. **Frontend Hosting &amp; Edge Delivery (`Vercel`):**
   - Pushing to the `main` branch on GitHub automatically deploys the static frontend (`index.html`, `assets/css/styles.css`, `assets/js/script.js`, WebP/SVG plates, and all-intra `.mp4` scrub assets) to Vercel's global Edge CDN with automatic HTTPS/TLS termination and `HTTP 206 Partial Content` byte-range streaming for smooth video scrubbing.
2. **Serverless Visitor API ([`api/visitors.js`](api/visitors.js)):**
   - Exposes `GET /api/visitors` as a Vercel Node.js Serverless Function.
   - Rejects non-`GET` requests immediately with `HTTP 405 Method Not Allowed` (`{ "error": "Method not allowed" }`).
   - Validates that `process.env.DATABASE_URL` is present server-side before attempting a connection, returning a clean `HTTP 500` (`{ "error": "Database is not configured" }`) rather than leaking stack traces or connection details.
3. **Relational Persistence &amp; Atomic Counter Update (`Neon Serverless PostgreSQL`):**
   - Connects via `@neondatabase/serverless` and executes a single-statement atomic PostgreSQL upsert so concurrent page loads never suffer from read-modify-write race conditions:
   ```sql
   INSERT INTO visitor_counter (id, count)
   VALUES (1, 1)
   ON CONFLICT (id)
   DO UPDATE SET count = visitor_counter.count + 1
   RETURNING count;
   ```
4. **Client Telemetry &amp; Local Loopback Protection ([`assets/js/script.js`](assets/js/script.js)):**
   - In production, `updateCounter()` requests `GET /api/visitors`, measures round-trip latency, and updates the live counter displays (`#hero-visitors`, `#dossier-visitors`, `#visitor-count`).
   - On local preview hosts (`localhost`, `127.0.0.1`, `::1`, `file:`), `isLocalPreviewEnvironment()` returns a deterministic local mock (`101`) by default so development reloads and automated browser tests never inflate the production Neon database.

## Engineering Decisions &amp; Lessons Learned

1. **Migrating from Phase 1 Azure to Vercel + Neon PostgreSQL:**
   - Building Phase 1 on Azure Storage (`$web`), Azure Functions, and Azure Table Storage taught me manual cloud resource provisioning, storage container permissions, and split CI/CD workflows (`static-site-deploy.yml` and `function-app-deploy.yml`).
   - Migrating active production to Vercel and Neon Serverless PostgreSQL unified static edge delivery and serverless API routing under a single Git-driven deployment pipeline while eliminating subscription cost friction and cold-start overhead.
2. **Choosing Neon Serverless PostgreSQL for Persistent Visitor Counting:**
   - Moving from a NoSQL key-value entity in Azure Table Storage to PostgreSQL enabled strict relational constraints and native single-statement atomic upserts (`ON CONFLICT (id) DO UPDATE`) over HTTP/WebSockets via `@neondatabase/serverless`.
3. **Keeping Database Credentials Strictly Server-Side:**
   - The browser only ever communicates with the same-origin `/api/visitors` route. `DATABASE_URL` lives exclusively in Vercel's encrypted environment configuration and gitignored local `.env.local` files, preventing credential exposure in client bundles or git history.
4. **Protecting Production Telemetry from Local &amp; Automated Test Traffic:**
   - Automated browser verification reloads pages dozens of times. Guarding `updateCounter()` with `isLocalPreviewEnvironment()` ensures `localhost` and `127.0.0.1` use a deterministic mock (`101`) while production visitors hit Neon PostgreSQL (with `?live_visitors=1` available when explicitly testing the live endpoint locally).
5. **Restructuring Two Videos into Independent Scroll-Scrubbed Experiences:**
   - Combining two different videos into one continuous timeline diluted their visual pacing. Separating them into **Study I (`#video-one`, Deep Plum Studio)** and **Study II (`#video-two`, Warm Parchment Right-Side Split-Screen)** — with Wave I project case studies in between and all-intra (`-g 1 -bf 0`) keyframe encoding — eliminated frame-seeking lag and gave each study a distinct narrative role.
6. **Designing for Reduced Motion, Keyboard Navigation &amp; Screen Readers:**
   - Scroll-scrubbed videos and looping GIFs can cause visual fatigue. When `prefers-reduced-motion: reduce` is active, both video stages lock onto high-resolution static WebP plates (`data-video-state="reduced-motion"`) and all animated project GIFs initialize paused on static WebP posters alongside keyboard-accessible WCAG 2.2.2 **Pause / Play animation** toggles.
